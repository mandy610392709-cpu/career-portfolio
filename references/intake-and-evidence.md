# 补料与证据

questions.json示例（引用内容须换成当前简历真实片段）：

```json
[
  {"type":"materials","resume_excerpt":"负责社团公众号内容","question":"这段公众号经历，有没有你写的推文、选题表或后台截图？没有更多材料也可以直接告诉我。"},
  {"type":"role","resume_excerpt":"参与迎新活动策划","question":"迎新项目里你独立负责哪些部分？有没有策划案或现场记录可以补充？"}
]
```

至少一项type为materials。少问泛泛的“还有吗”，优先找到最值得展示的1-3段经历。

- 内容/运营：原文、选题表、脚本、后台截图；发布数量、阅读量的口径及个人职责。
- 产品/市场：策划案、调研材料、流程图、活动物料、复盘；个人完成部分和实际落地范围。
- 设计/视频：原图、过程稿、视频链接、创作说明；区分独立设计、协作和临摹练习。
- 研发/数据：仓库/演示链接、界面截图、分析报告、架构；没有界面时用真实代码或报告节选。
- 校园/课程：课程报告、比赛方案、社团内容、演讲/志愿记录；保留课程项目、练习和未上线原型的标识。

项目、优势、技能和结果数字带source_ids，对应profile.evidence。活动照片不证明某个转化率，团队账号数据不直接写成个人独立成果。本人补充口述可以作为来源，不写成第三方验证。

重要事实缺失时最多追加一轮必要澄清，不影响准确性的细节可以省略。没有量化结果时用交付物、具体动作和复盘组成案例，不追着用户要数字。

脚本只能验证记录完整，不能判断答复是否真的来自用户。Agent必须保留真实对话对应关系。只有测试资料整体明确为虚构时才用demo=true；它会在网页与PDF每页显示虚构示例标识。
